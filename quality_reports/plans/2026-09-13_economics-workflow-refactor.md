## 1. 建议你先看这里

这次重构要解决的是：AI 能替你做更多工作，同时让你更容易判断研究问题是否值得做、证据支持什么、下一步为什么这样走，并在过程中学到新的经济学方法。

我的建议是保留现有 Claude Code 工作流和 Stata 优先习惯，重写协作、写作和质量控制的核心规则，修复实际运行缺陷。日常围绕一份简短的项目主线说明展开；详细材料按需展开。常规任务直接做，关键研究选择给出有证据的建议供你决定。

交付分成两版：**原位置继续是 Claude 版，保留 `CLAUDE.md`、`.claude/` 及现有文件、agent、skill 和命令名称，只更新其内容；根目录新建 `gpt-workflow/`，将更新后的研究流程完整迁移为 GPT/Codex 版。** 新增能力沿用各自平台的命名约定；两版均有独立入口、配置和使用说明，可分别复制到实际研究项目。具体见第 8.4 节。

最重要的六项变化：

1. **研究搭档成为默认模式。** 开放讨论、独立判断、解释机制、帮助学习；全流程执行需要明确的任务范围，不再由一个评分自动决定项目向哪里走。
2. **主线可见，也允许被证据推翻。** 每项重要结果说明它回答哪个问题、排除了什么、尚不能说明什么；新增探索要说明为什么值得做。
3. **写作按语言、体例、领域和读者调整。** 从真实论文提炼表达方式，保留你的声音；先修逻辑与证据，再修句子。
4. **前沿检索与创新讨论连起来。** 区分已知结论、相邻文献、我们的推测，主动提出有经济机制和最小检验的探索方向。
5. **代码保持容易介入。** 直接、清晰、少抽象；把真正影响实证可信度的检查放在关键位置。
6. **用可核实的检查替换自动评分通关。** 修正 hooks、复现要求和错误方法示例；明确哪些通过、哪些尚未验证。

本计划已经获得明确批准。普通实现细节不再逐项询问；只有影响研究含义、超出已确认范围，或环境确实要求权限时，才提出具体问题。

## 4. 协作方式：看得见的主线，适度的自主执行

### 4.1 默认模式与决策边界

默认是研究搭档：主动提出判断、指出弱点、比较替代解释，并完成当前任务中已授权的工作。检索、修复代码、整理证据、局部改写和可逆的必要核验，不因为流程模板再问一次。

需要交给你的选择包括：更换核心研究问题或主要 estimand；改变会影响结论解释的主样本或主规格；选择一个高成本新方向；把探索性结果升级为主要贡献；对外发送或正式投稿。提出这些选择时，先准备有证据的建议、替代方案、代价与后果，避免空泛地问“接下来做什么”。已明确授权的选择不重复确认。

`/new-project` 默认完成研究设定和第一阶段的具体工作，不从一句想法自动跑到投稿。你可以明确授权更长的执行范围。讨论中的分歧和失败结果保留，不因希望“故事顺畅”而删去反证。

### 4.2 项目状态尽量少而有用

真实项目按需使用三份核心材料；早期通常只建项目主线说明，有重要证据和决定后再建另外两份。工作流库提供模板，空项目不制造虚构研究进展：

| 材料 | 用途 | 更新时机 |
|---|---|---|
| `research/PROJECT_BRIEF.md` | 约一页：问题、为什么重要、当前机制与替代解释、主要证据/缺口、当前主线、下一步、待你判断的事项 | 实质研究判断变化或交接时 |
| `research/EVIDENCE_LEDGER.md` | 主要主张对应文献或输出、样本/单位/规格、反证、证据类型、验证状态和来源路径 | 新增、改变或作废重要证据时 |
| `research/DECISIONS.md` | 重要选择、理由、替代方案、由谁确认，以及什么证据会使其重开 | 重大选择时简短追加 |

文献地图、详细推导、学习笔记和探索代码按需创建，通过链接进入。默认不要求你阅读每个 agent 的日志，也不为每轮对话增加多份表格。

`/checkpoint` 负责更新当前状态和最少的交接信息；旧 session logs 保留。停止把同一决定重复写入四五个文件。恢复时识别具体项目、当前任务与已确认状态，不只凭最新文件时间判断哪个计划有效。

决策状态明确区分建议中、已确认和已替代，记录决定人。AI 的推荐不能自动写成你的选择；同一项目的不同会话也不能互相覆盖待办和授权状态。

“主线”是当前最有证据的组织方式，不是预设答案。每条主要结果都说明：支持、反驳、区分了哪种解释，或者暂时不具判别力。样本、代码、数据版本或模型改变后，受影响结果和稿件主张标记为待重验。

### 4.3 每轮研究讨论如何推进

每轮实质研究讨论，结合需要回答：我们刚学到了什么；什么仍不确定；哪个下一步最能改善判断。通常给一个首选探索，必要时增加一两个替代或跨领域方向，并说明机制、证据基础、可行性和最小检验。简单操作对话不强行附加创新清单。

探索方向可以跨度很大，但不自动变成正在执行的项目。早期允许充分发散；进入实证后围绕当前关键问题安排工作。候选方向记录何时值得重开；不按固定数量机械砍掉有价值的思路，也不无限积累 robustness。

例如，讨论“AI 是否减少招聘”时，可以区分任务替代、需求扩张、组织调整与招聘渠道迁移。下一步应优先找能区分解释的证据；在没有研究设定和数据前，不将其中任何一个写成该项目的发现。

## 5. 文献前沿、创新与经济学训练

### 5.1 文献工作从“列清单”转向判断贡献

`/discover` 增加明确的 `brainstorm` 和 `frontier` 模式，并兼容已有用法。检索先围绕经济问题、机制、测量和识别，而不是先列熟悉的方法名称。

重要文献记录：题名、作者、版本与日期、可追溯链接、读取范围、核心问题/机制/识别、与本项目关系。将“已读全文”“只核验摘要”“二手提及”“暂未核实”分清；工作论文与期刊版去重并记录差异。来源优先为论文原文、作者/机构页面、期刊、NBER、CEPR 和方法作者文档。取消因 working papers 占比超过 50% 就负面评价的规则，按相关性、证据质量和版本状态判断。

“前沿”指在当次任务中按检索日期核验过的相关研究；不把固定名单长期称为最新。重要贡献判断检查最接近的论文、相反结果和相邻领域，区分“在本次检索范围内未找到”与“从未有人做过”。检索不可用时保留推测标签，不宣称已经核验新颖性。

创新建议至少讲清楚新的经济机制或问题在哪里、什么结果会推翻它、现有数据是否能区分它，以及值得先做的小步骤。将贡献的新颖性、重要性、可识别性和可行性分开讨论；不因为短期较难就淘汰有潜力的方向。

### 5.2 理论支持与学习是核心工作

将 `/strategize` 扩展为机制、识别、正式理论和主线整理等按需入口。机制建模和正式证明区分：实证论文可以用一个小模型澄清直觉，纯理论论文也无需先有数据或通过代码审查。

新增一个独立入口 `/learn [概念或方法]`，同时让其他技能在遇到学习机会时主动解释。默认顺序是：

1. 这个工具解决什么经济问题，为什么当前项目可能需要它。
2. 用最小 toy model 或具体例子建立直觉，明确参与者、选择、约束和时序。
3. 定义对象、假设与关键推导，区分数学结论和经济解释。
4. 说明什么可观察、什么可识别；区分校准、估计、预测和因果解释。
5. 给出可能的实证含义、适用边界、替代方法，以及一两项可继续学习或复现的材料。

按需要深入均衡、搜寻匹配、任务模型、合约与信息、市场势力、结构估计等方向；这些是可调用的思路，不是每个项目必须装上的模块。主动推荐陌生工具时说明它带来的额外洞见与学习成本，不因你尚不熟悉而回避，也不因方法复杂就认为它更好。

关键证明要列清条件、边界情形和反例检验。数值模拟可以检查直觉，不能冒充证明。学习笔记只在有复用价值时保存，可选小练习，不强制把每次讨论变成考试。

## 6. 写作系统：语言、体例、领域和个人声音分层处理

### 6.1 四类基础体例

| 体例 | 重点 |
|---|---|
| 英文学术论文 | 经济问题与贡献、识别逻辑、精确动词、明确主语、恰当的限定；章节结构随研究类型变化 |
| 中文学术论文 | 符合中文的句法和论证节奏，术语稳定，减少翻译腔与堆砌；兼顾经济机制、制度背景和证据 |
| 中文政策报告 | 围绕读者的实际决策组织：问题、证据、政策选项、执行约束、分配影响和不确定性；避免口号化 |
| 英文政策报告 | 明确受众、政策选项、权衡、证据强弱及可执行含义；与论文的贡献论述区分 |

学术分支进一步支持实证、理论、方法及理论与实证结合。内部研究备忘录保持轻量，不强套投稿格式。已有 Word、LaTeX 或其他主稿沿用用户指定格式；大幅修改另存版本并保留可审阅差异，不强制转换为 `main.tex`。

### 6.2 从真实样本学习写法

按“语言/体例 → 领域/研究类型 → 当前任务的 exemplar → 你的修改偏好”组织按需 reference。共同底线是准确、清晰、有读者意识；期刊格式不能替代写作判断。

实施时先为劳动经济学、技术变迁与 AI 相关研究建立一个精简、核验过的示范样本集；其他领域在实际写作时扩展。每次选少量最贴近问题和读者的高质量论文，兼顾代表性作品与近期研究。记录为什么适合作参考，不用作者名气代替适用性。

提炼的内容包括开篇如何提出问题、如何解释机制、如何连接证据、怎样限定结论、如何在段落中安排长短句。样本中的句长和常用词可作观察，不能变成比例配额；不复制整段或强行模仿某位作者的口头习惯。未看到全文就不声称已分析其全文风格。

你的明确修改优先于从样本推测出的偏好。没有你的满意样稿时，只采用已明确的写作要求和标为暂定的领域参考，不宣称已经提取出你的个人声音。`personal-style-guide.md` 允许直接修订，并区分已确认偏好和候选观察。

### 6.3 写作与审查顺序

`/write` 保留现有入口，增加语言、体例、领域和工作方式选项。支持提纲、起草、局部编辑和诊断；信息可从任务推断时不先做冗长访谈。

处理顺序：读者要理解什么 → 主张与证据是否对应 → 段落与章节是否服务主线 → 句子是否准确自然 → 格式与排版。编辑主稿时，区分原意澄清、结构调整和需要作者判断的实质变化。

移除机械词数、被动句比例和“禁词达标”式评分。检查空泛开场、无信息过渡、排比堆积、重复总结、语气过满和碎片化段落，但不能因此删除必要限定、改变专业术语，或把相关性改成因果。

结果润色必须保持系数、单位、基准组、样本、置信区间、识别条件和证据强度。前趋势检验不显著不等于平行趋势成立；描述性结果不因换成主动语态就变成处理效应。中英转换重新组织表达，但事实口径和不确定性一致。

## 7. 实证代码与研究质量控制

### 7.1 代码以易读、可跑、可检查为准

保留 Stata 优先；Python、R、Julia 等根据问题与可用实现选择，已有项目设置优先。MCP 是执行通道，分析逻辑仍保存为可复现的脚本。MCP 不可用时检测已配置的本地执行方式；没有可用运行环境就明确记录未运行，不假造输出。

默认使用少量按研究步骤命名的脚本和清楚的 master 入口。重复逻辑或真实复杂度出现后才抽函数，不预设类层级、通用 pipeline 框架或大段模板注释。每次交付指出研究者最可能修改的设定、运行入口和关键输出。

将现有 INV-22 调整为集中管理实质研究设定：样本窗口、处理定义、主结果、控制组、固定效应、聚类层级等。一次性简单表达无需全部包装成宏。保留分析与数据构建分离的原则，分析不覆盖原始数据或标准 cleaned 数据。

验证集中在会改变答案的环节：merge 基数、重复键、缺失和样本流失、权重、单位、处理时点、估计样本、标准误层级及结果导出。检查随研究设计选择，不对每个脚本套相同清单，也不要求所有估计都用第二种语言重复一遍。

### 7.2 将分数门槛改成证据与检查状态

废除 80/90/95 分作为 commit、PR、投稿的统一自动通关依据。内部审查区分：已证实的实质错误、尚缺证据的疑问、写作或格式建议。每个重要问题附定位、依据、影响和可行修复。

检查状态统一表达为通过、失败、未验证、不适用；“不适用”说明理由。未验证的必要检查不能通过重新分配权重消失。代码、数据或文本更新后，旧检查需要重新判断是否仍有效。

独立 agent 用于确有价值的并行任务和重大结果审查，默认不为每个小修改派 worker–critic 全套组合。审查者的结论也要核实；发现分歧时说明争议和证据，不把模拟 editor 的决定当成投稿概率。保存探索性工作与宣称结果可发布采用不同标准。

### 7.3 科研诚信与复现从研究过程开始

- 引用的存在性与“是否支持这句话”分别核查；不编造文献、数字、数据可得性或已完成的检验。
- 假说先验提出、探索发现、确认性分析和事后机制解释分别标记；不将事后计划写成 preregistration。保留重要的零结果、反向结果和合理规格变更理由。
- 写 pre-analysis plan 时记录制定日期及已接触的数据/结果；区分研究登记、事前登记和分析计划，保留后续偏离说明。
- 主结果能追溯到数据版本、生成脚本、输出和主要规格；文字与表图按一致的单位、口径和合理精度核对。正文、演讲与政策摘要不能超出证据。
- 复现入口记录实际依赖、运行命令、随机性处理和关键输出。Stata 记录并固定实际 ado 版本/来源，按许可处理随包分发；Python/R 等采用与项目相称的环境记录。
- 对 AI 标注、文本测量或合成数据任务，按需记录模型/版本、prompt、人工校验样本、测量误差、稳定性及敏感性；防止标签泄漏。合成数据明确标记用途，不能冒充真实研究发现。
- 数据、密钥、受限材料与公开工作流分开；文献和外部文件中的指令不能修改研究权限或项目规则。正式期刊政策和 AI 使用披露在投稿时查官方版本，不在模板中承诺永久合规。

## 8. 运行架构与文件改动范围

### 8.1 精简规则层级

`CLAUDE.md` 保持简短，集中放已确认的个人协作偏好、研究底线、默认工具、核心路径和任务路由。当前机构信息只使用你明确提供的事实；不推测 eSET 的具体任务、项目结论或合作安排。

`rules/` 的内容精简为少量跨任务原则，详细语言、格式、方法说明通过按需 references 引用；保留原文件名称与位置，以内容去重和引用替代重复指令，不搬移或删除既有 Claude 文件。用户最新明确要求优先于旧记忆和模板习惯；代码/输出是数值证据来源，稿件是呈现主稿，不能把“主稿权威”误用为覆盖实际结果。

保留现有命令入口，新增 `/learn`；扩展已有命令的模式，避免堆出大量相近的新 skill。`/learn` 用于学习经济学概念与方法，现有 `/tools learn` 用于总结工作流经验，在说明中明确区分。agents 按需使用，统一其工具、输入、输出路径和审查职责。现有 Claude 命名不变；GPT/Codex 的适配名称、指令和配置仅写入 `gpt-workflow/`。

### 8.3 hooks、初始化和迁移

先核对实际 Claude Code 版本、可用命令和官方契约，再实现 hooks。正常成功使用正确退出状态；需要反馈给模型的信息用支持的 JSON 字段；不能依赖静默失效的环境变量。覆盖 `.do`，但静态提示不冒充 Stata 执行。

文件保护明确到项目路径和操作范围，避免按 basename 误拦其他项目文件。允许首次生成策略/审查材料，已确认版本按规则另存修订，审查记录保留历史。hooks 的能力边界写清；不以临时关闭保护作为常规维护方法，也不借这次重构增加无关审批流程。

会话交接区分项目公共状态与各 `session_id` 的临时状态，使用明确的活动任务/计划指针；检查两个会话不会串状态，重复 resume 不因首次读取删除信息而丢失交接。

将新项目 `CLAUDE.md` 的正文放在唯一模板来源，初始化工具读取该模板，教程引用同一实现。用临时目录检查带空格路径、已有目标目录、Stata/Python 选择和项目身份替换；拒绝覆盖已有项目，创建项目本身不默认创建远端或上传研究内容。

旧项目升级采用按文件/变更范围核对，不建议删除整个 `.claude/`。本次只改库内实现和迁移文档；`~/.zshrc`、`~/.claude/`、`~/.codex/`、`~/.agents/`、已有论文项目和 Obsidian 不在自动修改范围内。需要时提供可审阅的调用方式，清楚标注尚未安装到全局环境。

### 8.4 Claude 与 GPT/Codex 两版独立交付

这里将“GPT 的语言”理解为：使用适合 GPT 的任务指令、工具调用约定、技能组织和验证方式，主要执行环境为 Codex。中文交流及中英分体例写作要求继续保留。先完成 Claude 版核心内容更新，再据此迁移 GPT/Codex 版；共同的经济学原则一致，平台能力分别适配，不靠替换品牌名完成迁移。

拟定目录如下；GPT 内部实现细节在实施时按本机版本核验，原 Claude 路径不变：

```text
claude-workflow/
├── CLAUDE.md                      # 原 Claude 入口，更新内容
├── .claude/                       # 原 skills/agents/rules/hooks，命名不变
├── templates/、scripts/、…         # 原 Claude 配套内容
└── gpt-workflow/                   # 新增，可单独复制使用
    ├── README.md                  # GPT/Codex 版独立上手说明
    ├── AGENTS.md                  # GPT/Codex 项目指令与任务路由
    ├── .agents/skills/            # 迁移后的研究技能及学习技能
    ├── .codex/                    # 按实际支持采用的项目配置/agent 定义
    ├── references/               # 研究、写作、方法与代码参考
    ├── templates/                # 项目、主线、证据与决策模板
    ├── scripts/、tests/           # 必要初始化与验证
    └── docs/                     # 功能对应表、平台差异与迁移记录
```

**迁移内容与方式：**

| Claude 侧内容 | GPT/Codex 侧处理 |
|---|---|
| `CLAUDE.md` 与常驻 rules | 改写为 `gpt-workflow/AGENTS.md` 的精简指令和明确的按需引用；不假设 Claude 的 rules 加载方式可原样沿用 |
| `.claude/skills/*/SKILL.md` 与 `/command` | 在 `.agents/skills/` 重写技能触发、步骤、工具和产出契约；保留 discover/write/learn 等语义，示例按目标客户端实际支持的调用方式编写 |
| `.claude/agents/*.md` | 保留经济学角色职责，按实际 Codex 子 agent 配置和委派能力适配；不可用时提供明确的串行审查路径，不声称运行过不存在的 agent |
| `.claude/settings.json`、权限与 MCP | 逐项映射到支持的项目设置；保留用户环境已有模型与权限选择，运行时识别 MCP 工具，不硬编码 Claude 工具名或假设连接已经建立 |
| hooks、checkpoint 和记忆 | 分别核对事件、输入与执行能力；有对应机制时适配，无对应机制时用技能中的显式交接/检查脚本完成，并标明是否自动触发 |
| 研究原则、写作体例、参考样本、代码规范和模板 | 完整迁移到新目录，修正内部路径；原始出处与证据强度保留，确保八项需求两版均覆盖 |
| 初始化、教程和验证 | 提供 GPT/Codex 版自己的入口与示例；分别说明启动位置、生成项目、恢复状态及验证方法 |

上述目录约定依据 OpenAI 官方的 [AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md)、[skills](https://learn.chatgpt.com/docs/build-skills)、[项目配置](https://learn.chatgpt.com/docs/config-file/config-basic)和[子 agents](https://learn.chatgpt.com/docs/agent-configuration/subagents)文档。规划阶段检测到本机 CLI 为 `codex-cli 0.154.0`；执行时再核对实际可用能力，版本号不是集成测试通过的证明。

**独立性与后续维护：**

- `gpt-workflow/` 所需的模板、参考材料与脚本都在自身目录内，不依赖 `../.claude/`、父目录 `CLAUDE.md` 或指向 Claude 文件的符号链接。可将整个目录复制出去独立使用。
- Claude 初始化继续沿用原入口，显式排除 `gpt-workflow/`；GPT 初始化只取新目录内容。避免一次初始化把两套 agent、配置和历史状态混装进同一论文项目。
- 两版的示例状态、运行日志和项目根路径分别管理，不把目录分开就当成已经隔离。检查父目录指令继承和客户端发现范围；正式独立性测试在仓库外临时目录完成。
- GPT 指令和配置不写入原仓库根目录的 `AGENTS.md`、`.agents/` 或 `.codex/`，避免影响原 Claude 版；此处仅指本次产物放置，不覆盖外部已经存在的个人指令。
- 迁移记录说明对应的 Claude 基线版本、功能映射和平台差异。以后共同研究规则改变时核对两版，平台特定设置分别维护；不引入自动双向同步系统。
- 分别提供支持、替代实现和未验证能力的清单。将两版用于同一实际论文的需求留到具体项目处理，先按你的要求支持分开使用。

### 9.1 行为验收场景

| 场景 | 应有行为 | 要发现的失败 |
|---|---|---|
| AI 与劳动需求 brainstorm | 核验最近相关研究，比较竞争机制，给有判别力的下一步；必要时提供跨领域候选 | 罗列熟悉文献、把推测当事实、自动铺开多个项目 |
| 零结果或符号翻转 | 先核对样本与实现，再评估证据对机制的含义，必要时建议调整主线 | 为保住原叙事挑显著规格或隐藏反证 |
| 陌生理论/方法 | 解释为何值得学，用 toy model、假设和推导连接实证问题 | 以“太难”为由排除，或只堆复杂术语 |
| 同一证据写四种体例 | 中英学术和政策文本各有组织方式；单位、数字和结论边界一致 | 逐句翻译、强套论文结构、政策建议超出证据 |
| 局部英文编辑 | 保留作者原意，改善节奏和逻辑；必要限定不丢 | 将 association 改成 effect，或把前趋势不显著写成假设获证 |
| Stata 样本处理与导出 | 清楚入口、关键设定和样本检查，结果能追溯且不污染下个规格 | MCP 跑了却无脚本、merge 后样本翻倍、单位错误 |
| 已知答案的合成小例子 | 用手算或已知 DGP 核对估计对象与样本；baseline/子样本分别正确保存，随机性可复现 | 保存了错误模型、丢弃 RNG、把两份实现一致当成正确性证明 |
| 模拟文献不存在/只读摘要 | 标记未核实或删除，不据此宣称创新性已证实 | 自动补出 DOI、作者和文献结论 |
| 变更代码后恢复会话 | 恢复当前已确认决定，将受影响输出标为待重验 | 把旧 PASS 或最新文件时间当成当前事实 |
| hooks、初始化与迁移 | 用符合实际契约的输入检查正常、错误和边界情况；迁移示例保留用户自定义 style/agent/state | hook 没运行却全绿、误拦普通文件、覆盖已有项目或定制 |
| 运行失败但旧输出仍存在 | 按本次退出状态与运行记录报告失败，指出哪些旧结果不能继续引用 | 根据文件存在或时间戳就报告通过 |
| 模板库没有论文/运行环境 | 检查可执行部分，明确不适用和未验证 | 编造论文编译、Stata 运行或正式投稿检查已通过 |
| Claude 命名保持 | 比较实施前后的现有路径、skill/agent 名称和入口；内容更新仍可沿用原用法 | 将 `CLAUDE.md` 改为 `AGENTS.md`，搬移/删除原 Claude 文件或改掉原命令 |
| GPT 版独立使用 | 将 `gpt-workflow/` 复制至仓库外临时目录，检查指令、技能、reference、模板与脚本发现和运行 | 离开父仓库就失效、引用 Claude 配置或只做品牌词替换 |
| 双版初始化与会话隔离 | 分别生成示例项目并恢复各自状态，分别运行 brainstorm/写作/学习/核验场景 | 混装两套配置、读错另一版状态、把一版通过当成两版均通过 |

### 9.2 自动检查与人工判断分开

自动检查保持轻量：JSON/脚本语法、内部链接与引用路径、skill/agent 路由、旧规则冲突、hooks 的正常与故障输入、初始化的关键边界。规则冲突扫描限定当前生效的配置和文档，不把历史计划、日志、CHANGELOG 中对旧规则的记载误判为失败。重要检查使用故意引入的错误和正常对照，避免测试只复述实现。

经济机制、创新性、表达自然度和读者体验需要行为演练与审阅，不能靠关键词扫描或模型给自己打分认证。若可调用实际 Claude Code，则在隔离示例中做真实 smoke test；否则交付可复用场景，并明确“配置检查完成，Claude Code 行为尚未实测”。Stata、LaTeX 等同理。

GPT/Codex 版另做对应的配置、内部路径和技能契约检查，并在可用环境中进行实际 smoke test。两版分别报告结果；对研究主线、创新、体例和学习等共同需求，比较行为是否符合相同原则，不要求两种模型给出相同措辞或相同候选想法。

必要检查通过后不反复跑同一套流程凑数量。发现新错误才扩大检查。正式交付附一份简洁验证记录，区分静态审查、编译、分析运行、行为审查和环境限制；一种检查通过不能代替另一种。
