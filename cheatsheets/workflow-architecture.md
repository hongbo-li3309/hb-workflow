# 工作流架构与迁移

当前库有两个可独立使用的版本：原位置的 `CLAUDE.md` / `.claude/`，以及 `gpt-workflow/` 的 `AGENTS.md` / `.agents/skills/`。现有Claude命名与路径保持；GPT版有自身引用、模板、脚本和配置。

每篇论文生成独立项目，默认不携带库的Git历史、演示结果、会话状态或另一版。不要把 `.claude/` 的 settings、hooks或工具名直接放进GPT版，也不要使GPT技能依赖 `../.claude/`。初始化入口分别在各版 `scripts/new_project.py`。

## 三类信息

| 信息 | 放在哪里 |
|---|---|
| 通用研究、写作、代码方法 | 库的rules/references/skills；按需加载 |
| 具体问题、证据与决定 | 项目research目录；PROJECT_BRIEF为最短恢复入口 |
| 本机配置、访问凭据和临时会话 | 客户端本地配置与忽略状态文件；不要进入公开版本 |

用户最新明确决定优先。自动记忆和hooks不能替研究者做选择；两版的会话状态独立。对同一论文换工具时，先指定主稿与已确认状态，再明确当次任务，不能靠文件夹名称推测。

## 升级已有项目

1. 确认项目使用哪个版本，保存既有改动和用户定制基线。
2. 比较候选库版本，列出实际需要的文件与行为差异。
3. 在当前版本上应用相关内容变化，保留用户style、agents、local settings、数据和稿件。
4. 运行相关检查与一个真实使用场景，未执行部分明确NOT_RUN。

不要删除整个配置目录、自动覆盖全局shell文件或强制更新模型。现有名称不是需要清理的“遗留”；维护内容与引用即可。用户层也可以有技能/配置，具体发现规则由客户端决定，“只能项目级”不是通用事实。
